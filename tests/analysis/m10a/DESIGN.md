**Status: prepared, not executed.** The campaign runs in a later batch, after review.

- **Branch:** `m10-a-consolidation`, from `m9-j1-resolution-fix` `5f0be9d`.
- **Results (at execution):** `tests/results/m10a_dev_configuration_20261020/`.
- **Pre-freeze development (disclosed):**
  - the composer gate, 8/8;
  - two scratchpad dry runs of the comparator controls, on saved runs only (about 3 s in all). The first run failed C2: the

## 1. The configuration: three layers

| layer | file | content | varies with |
|---|---|---|---|
| 1a | `profiles/genotype_dev_performance_v1.tsv` (unchanged, sha256 `cc71ead4…`) | exact performance backends, cache budgets, consumption caps, `timing_detail` | nothing (common) |
| 1b | `profiles/genotype_dev_m10a_v1.tsv` (new) | retained route: `early_incumbent experimental_v1`, `union_fragment_blocks fine_core_4096_experimental`, `repair_round1_origin_admission reuse_only_experimental`. **Experimental scientific switch:** `repair_junction_proposals experimental_v1` (JP1.1). **Contract and annotation:** `output_schema sequence_first_v2`, `compound_annotation contract_v2`. Stated explicitly at its default: `repair_joint_search off` | nothing (common) |
| 2 | `compound_interval_declarations_v1`, one artifact per **model fingerprint** | declared compound intervals, bound to the fingerprint and the ordered block ids | the model (graph, reference, curation, marker settings) |
| 3 | the cell's base profile (`genotype_perf_bounded_20261015/inputs/profiles/<cell>.tsv`) | `time_limit_seconds`, `footprint_limit_bytes` (6 GiB), `max_state_classes` (600 M), `repair_max_neighbours` (CYP2D6 958, ACOT 1004, C4 default 670) | locus and input |

**Common command flags:** `--preset short-read --dosage-mode audit --threads 4`.

**Composition** (`compose_m10a.py`) produces one profile per run, listing every input with its SHA-256.
- Layer 3 may hold **resource keys only**; any other key is refused.
- Layer 1b keys must match its declared sections exactly.
- No key may come from two layers.
- Overrides are limited to the time and footprint guards, under `compose_profile.py`'s rules.

**Not standardised:**
- **Model settings** are the short-read preset's, unchanged. M9-H's ACOT profile restated `copying_transition constant_v1`
  and `switch_probability 0.01`; both equal the default and preset values, so nothing changes.
- **`repair_max_neighbours` is a resource requirement, not a model setting.** Exceeding it stops the run as
  `REPAIR_INCOMPLETE` ("refused before any allocation", `genotype_command.cpp`). It never changes a completed result, so it
  stays per locus.
- **What this configuration changes relative to the M9-J.1 checkpoint:**
  - C4 and CYP2D6 now run JP1.1, which has never been run there.
  - ACOT now runs the retained route, which M9-H did not use.

  The plan tests both.

**Model-bound declarations.** The development cells' models differ from the M9-J smoke models: no LOO curation, and full
graphs.
- Their fingerprints, recorded by S2-L for the same inputs, are C4 `d2b8c6c2…`, CYP2D6 `2a5b720a…` and ACOT `d622742f…`.
- New artifacts are generated by the `declare` unit, with the M9-J tools: `cyp2d6_block_alleles`, then
  `degeneracy_inventory.py`. The unit fails if a dump fingerprint differs from S2-L's.
- The M9-J artifacts remain valid for their own models only.

| `route` O vs D0 | 5×, C4/CYP2D6 30× | retained-route equivalence | as above; effective settings equal except the three route keys; trajectory equal | S2-L v3.2 `operational, profile, route, admission, checkpoints` plus `incumbent` (one-sided `early_incumbent*` / `checkpoint_*` rows and the early evaluation's work counters) |

**Comparator controls** (unit `controls`, before any caller run; 10 cases, all on saved runs or relocated copies):
- positive: S2-L control vs combined; S2-A off vs on; P1 opt vs reference; S2-L repeat; JP eligible-0 identity;
  JP-attributable; prepared rows;
- negative, each failing for its own reason: an altered score under `route`; an altered score under `jp` with eligible 0;
  an undeclared setting under `prepared`.

**Stated gaps** (not hidden):
- **ACOT 30× backend and route.** O (the ordinary route) refuses ACOT 30× at the 500 M physical-origin cap under 6 GiB
  (S2-L control), and REF at 30× is outside this budget (P1 limitation). So ACOT 30× has **no** `backend` or `route`
  comparison. Its evidence is S2-G's bit-identical reference with validation-only cap extensions, on an earlier source.
- **30× backend.** Only C4 and CYP2D6 30× are tested, and only for `route`. `backend` is 5× only.
- **Concurrency.** Concurrent caller invocations in one process are not tested. P is **sequential** reuse (the I3-A
  contract).

**Expectations (from S2-L's combined arm on an earlier source; not acceptance criteria):**
- every run completes in round 1;
- CYP2D6 30× is a completed sv:3/sv:5 tie (`CONDITIONAL_GENOTYPE_EQUIVALENT`), which is comparable;
- ACOT 30× about 104 s and 4.5 GB.

Nothing is accepted against saved S2-L outputs: the results tree is stale relative to this source, so every comparison is
between arms of this campaign, on one build.

**JP1.1 eligibility** is unknown before running for C4, CYP2D6 and the full-panel ACOT model. The `jp` rule decides it from
each D run's own status.

## 4. Execution rules (frozen)

1. **Order** (`m10a_run.py` manifest P, 60 units): build, then the gates (composer, compound, JP1.1, sequence report,
   e2e `sequence_first`, e2e `prepared_locus`), controls and declare; then per 5× cell REF, O, D0, D and its comparisons;
   then 30×; then the persisted-index units; then the repeat and the summary. One process at a time, `nice`, 4 threads.
2. **Stop rules:**
   - a gate, control or declaration failure stops the campaign before any caller run;
   - a **failed** `backend`, `route`, `prepared` or `repeat` comparison stops all further caller runs until a declared
     amendment;
   - a `JP_ATTRIBUTABLE` result never stops;
   - a comparator failure that touches only non-scientific status keys stays recorded. Any amendment names the inspected
     keys and their values (the M9-J A4 pattern). No scientific file, column or setting is ever excused.
3. **Resource outcomes.** A refusal, time limit or footprint stop makes the pair `UNRESOLVED`, reported as a resource
   limitation. No guard is relaxed.
4. **Conditional unit.** `loaded.acot.single30` runs **only if** the two-sample ACOT process does not deliver a completed
   30× sample. A footprint ratchet across samples is the known I3-A.1 behaviour. Its comparison then replaces
   `cmp.prepared.acot_30`.
5. **Budget:** 2,400 s. A unit runs only if spent + its declared timeout ≤ 2,400. Expected spend is about 1,600 s. Units
   that do not fit are recorded `NOT RUN`.
6. **No timing claims beyond description.** Wall times are reported per run. Off/on speed effects are not inferred: runs
   are sequential, but machine load is not controlled.

## 5. What the results will and will not mean

**If every `backend`, `route`, `prepared` and `repeat` comparison passes:** the computational route of
`genotype-dev-m10a-v1` (backends, retained route, persisted index, determinism) is validated on these six cells, within the
stated gaps.

**`jp` results** describe what JP1.1 changes on these cells. They are **not** accuracy: no truth is used.

**Not established:**
- correctness;
- calibration;
- behaviour on other loci;
- concurrent in-process use;
- any default.

## Amendment 1 (prospective preflight; declared before any campaign unit ran)

**Defect (Sol's review).** Sol built two copies of S2-L `combined.c4_5`, with `junction_eligible_blocks 1` and
`mismatch_band` 6 → 7. The underlying comparator rejected the settings difference, but `jp` overrode it with
`JP_ATTRIBUTABLE`, exit 0. Reproducer: `/private/tmp/panvar-m10a-review.788IMa/`, copied into the `controls` unit.

**Corrected `jp`** (`m10a_compare.py`). JP eligibility may change candidates, trajectory, predictions and their
annotations. It never waives the invariants below, which are checked in order; any violation is FAIL:
- **J1** `junction_eligible_blocks` is a nonnegative integer. The off arm has no JP rows or setting. The on arm runs
  `experimental_v1`.
- **J2** Required outputs are present, non-empty and have a TSV header in both arms: settings, status, scores, candidates,
  rounds, the sequence locus, blocks, alternatives and haplotypes, plus `sequence_compound.tsv` when the annotation is on.
  The prediction is one of PREDICTION, PROVISIONAL or NO_PREDICTION.
- **J3** Effective settings have equal key sets and values, except `repair_junction_proposals`. This covers every
  scientific setting and every configured cap in the settings table.
- **J4** Protected status keys are equal:
  - input, model and library identity: `model_fingerprint`, `sha256_*`, `gfa`, `reference_path`, locus geometry and
    transition digests, `library_provenance`, `curation_digest`;
  - configured caps and budgets: `max_*`, `*_limit_*`, `*_budget_*`, `*_budgeted_bytes`, `proposal_state_limit`,
    `representation_guard_bound_nats`, `union_cap*`, `threads_requested`.
- **Eligible 0:** full s2l v3.2 identity, as before.
- **Eligible > 0 — J5:** every hypothesis scored in both arms has **exactly equal printed** objective components (`score`,
  `fragment_term`, `exposure_term`, `sequence_pair_prior`, `numeric_error_bound`, `fragments_with_mass`,
  `fragments_total`, `mismatch_band`), and its labelling's `exact_path_prior` is equal too.
  - **Matching.** Hypotheses are matched by **labelling**, the unordered pair of allele tuples, never by candidate or group
    id.
  - **Excluded.** `candidate_set_probability` changes legitimately with pool membership.
  - **Non-vacuous.** At least one common hypothesis is required.
  - **Why exact equality.** It was audited on three real saved JP off/on pairs (M9-H L4, L2, Z1): 89,442, 93,513 and
    84,458 common labellings, all components identical as printed; only `candidate_set_probability` differed.

  Only after J1–J5 pass is the verdict `JP_ATTRIBUTABLE`.

**Corrected and added controls** (18, unit `controls`). Each must give its expected exit **and** contain its intended
reason. The `score` control now edits the column named `score`; it previously edited the last column,
`carries_called_genotype`.
- **Positive controls:**
  - C1, C2, C7, C9 and C10 as before;
  - **J1:** the real saved JP off/on pair M9-H L4 (JP1.1 changed the search; 89,442 common hypotheses) gives
    JP_ATTRIBUTABLE;
  - **J2:** an eligible-0 copy gives identity.
- **Negative controls:**
  - C3: the score column altered;
  - C8: an undeclared setting;
  - **N0:** Sol's reproducer. It fails on J3, and also on J1, because its B has no JP setting;
  - **N1:** real pair with an unrelated scientific setting changed (J3);
  - **N2:** an undeclared cap changed in settings (J3);
  - **N3:** a configured cap changed in status only (J4);
  - **N4:** input identity changed (J4);
  - **N5:** a common hypothesis's `fragment_term` corrupted (J5);
  - **N6:** a required output missing (J2);
  - **N7:** eligible 0 with a changed score (identity);
  - **N8:** eligibility `-1` (J1).
- **Development dry run:** 18/18 in 5.5 s, each negative with exactly its intended problem.

**Runner:**
- A **failed `jp` comparison stops further caller runs**, like the other equivalence comparisons.
- `JP_ATTRIBUTABLE` (exit 0) and resource `UNRESOLVED` (exit 2) never stop.
- Comparison timeouts are 30 s.
- **Before admitting any caller unit**, the declared timeouts of every comparison and the summary still to run are reserved:
  spent + unit timeout + reserve ≤ 2,400 s.
- Disclosed development time, 30 s, counts against the budget.

**Summary.** Adds the driver phase tables (index write/verify, load, each sample, cleanup, and current and lifetime peak
footprint), the batch verdicts and a copy of the ledger.

**Reporting of index reuse** keeps three things separate:
1. cold-vs-indexed scientific equivalence, per sample;
2. whether the **sequential** 5×-then-30× process completed;
3. the conditional fresh-process fallback (`loaded.acot.single30`). It can establish single-sample loaded-index equivalence,
   but never that the sequential batch completed.

Each locus's two workloads are two coverages of **one** donor. They are not validation across biological samples.

## Amendment 2 (after `cmp.route.c4_5` and `cmp.jp.c4_5` failed; no caller run since)

**What failed.** Both C4 5× comparisons failed on **status keys only**. Every scientific file is byte-identical across REF,
O, D0 and D: genotypes, scores, sequence locus and compound annotation have the same SHA-256 in all four arms.
`cmp.backend.c4_5` passed. JP1.1 reported `junction_eligible_blocks 0` on C4. The keys outside the declared categories, with
their inspected values:
- `compound_seconds` (route and jp): the annotation's own timer, 0.000144 against 0.000155 s;
- `footprint_checkpoint<N>_{phys_footprint_bytes, phys_footprint_peak_bytes, allocator_in_use_bytes, seconds}` (jp only):
  14 checkpoints in both arms, with identical stage names; only the measured bytes and seconds differ. The `checkpoints`
  category already covers these in `route` and `repeat`; I left it out of `jp`;
- `repair_junction_proposals` in status, present in D only: the echo of the declared setting, whose value J3 checks in the
  settings table.

**Fix:**
- `compound_seconds` is operational timing in every mode.
- `checkpoints` is added to `jp`.
- The one-sided status echo `repair_junction_proposals` joins the `junction` category.
- **Prospectively**, `checkpoints` is also added to `prepared`, because cold and loaded runs measure footprints differently.

No scientific file, column, setting, identity key or cap is excused.

**Reruns (manifest A2):**
- `controls.a2` replaces `controls` as the caller precondition;
- `cmp.route.c4_5.a2` and `cmp.jp.c4_5.a2` are re-evaluated on the **same saved runs** (no caller rerun);
- `REF/O/D0/D.cyp_5.a2` and their three comparisons. The stop recorded the original CYP2D6 5× units as NOT RUN; they keep
  those ledger rows.

**Then** manifest P continues with its remaining units. Comparisons that name a CYP2D6 5× arm resolve to the `.a2` run
directories. A superseded failure stops nothing once its replacement passes.

Disclosed development time for this amendment: 10 s, counted in the budget.

## Amendment 3 (after `cmp.jp.acot_5` failed; no caller run since)

**What failed.** `cmp.jp.acot_5` failed J3 and J4 on exactly one key, `time_limit_seconds`, 130 against 160, in the
settings table and its status echo.
- **Cause: my plan.** The frozen plan gives D a larger timeout than D0 for ACOT 5× and for every 30× cell (150/180,
  300/360). The time guard is the declared timeout minus 20 s.
- **Not a run problem.** Both runs completed. JP1.1 was eligible (1 block). No other invariant was reached or violated.

**Fix.** In `jp` mode only, `time_limit_seconds` is a **declared operational guard difference**: J3 and J4 skip it, and the
underlying identity check declares it. Its two values are reported. It is accepted only on top of the outcome check, which
requires both runs to be complete. Every other setting, identity key, cap and budget stays protected.

**Reruns:** `controls.a3` (it must still pass 18/18) and `cmp.jp.acot_5.a3` on the same saved runs. Then manifest P
continues. Disclosed development time for Amendments 2–3: 15 s in all.
