# M9-J: minimal, opt-in integration of compound annotations (M9-I.1 contract v2)

**This closes the diagnostic prototype stage.** It implements the validated annotation; it is not another model or search
redesign.

**Results:** `tests/results/m9j_compound_integration_20261020/`.

## Scope (frozen)

**New:** `<prefix>.sequence_compound.tsv`, beside `sequence_blocks`.

**Opt-in profile keys:**
- `compound_annotation off|contract_v2`, default off;
- `compound_interval_declarations <file>`, optional.

**Refusals:** `contract_v2` without `output_schema sequence_first_v2`, and declarations without the annotation. A malformed
declaration file is refused before the prefix.

**Unchanged:** predictions, candidates, scores, priors, search, block rows, phase assertions, GQ, filters, FASTA policy and
dosage.
- **Off:** no new file, no new status or settings row.
- **On:** the declared provenance only, namely the settings rows for the two keys and the `mosaic_status` rows
  `compound_annotation`, `compound_declaration_status`, `compound_declaration_sha256`, `compound_intervals` and
  `compound_seconds`.

**Code:**
- `include/panvar/compound_annotation.hpp` and `src/compound_annotation.cpp`: a model-agnostic helper;
- `genotype_sequence_report.*`: the `SequenceReport::compound` field, the write before the locus commit record, the owned
  suffixes and the status keys;
- `genotype_command.*`: options and refusals, declaration loading, and the pooled, provisional and no-prediction hooks.

## Declarations

**The artifact:** `compound_interval_declarations_v1` files, generated by `m9j.py declare` from **existing** model
inventories.
- **Content:** the model fingerprint, the model's **ordered block ids**, and intervals as consecutive block-id lists, each
  with its source.
- **Validation at run time:** the fingerprint must equal the active model's and the ordered block ids must be identical,
  otherwise INVALID_FINGERPRINT or INVALID_BLOCK_IDS, and the declarations are dropped. Interval blocks must be
  consecutive.
- **Coalescing:** declarations are coalesced with the run's representation intervals. Overlapping spans merge; adjacent
  spans do not. Each row records its sources.
- **Constraints:** no locus names or coordinates in library code; no per-sample degeneracy search (only per-model
  artifact generation from existing tools); the persisted index format is unchanged.
- **Scope string:** conservative, not minimal or exhaustive.

## Computation (contract v2)

**Inputs:**
- the full in-memory `PooledDecision`: every sequence group, every recorded labelling of it, and its full-precision
  `candidate_set_probability`, zero-mass (underflowed) groups included;
- the decision set, `top_groups`;
- the representative labelling.

**Target interning.** Exact interval bytes are interned by byte comparison; there is no hash in grouping.

**Masses and bounds:**
- masses are validated, then normalised with Neumaier summation in group order (deterministic);
- every bound is a direct compensated sum;
- missing projections go into both upper bounds only;
- empty pools are UNASSESSED and invalid inputs INVALID, and the prediction is untouched either way.

**Competitor status** is decided from projections, independently of mass.

**Target resolution:**
- RESOLVED when every recorded labelling of every decision-set group projects to one target;
- otherwise UNRESOLVED_DECISION_SET, with the projections listed and `mass_reference
  representative_projection_only_not_a_resolved_target`.

**Without a completed pool:** provisional reports get NOT_ASSESSED_PROVISIONAL rows with no bounds; no-prediction reports
get the file with no rows.

**Lifecycle:** the file is an owned sequence-report output, removed at run start and on publication failure, and written
before the locus commit record.

  and otherwise ≤ 1e-9 relative. The caller uses full precision, the replay 12-digit printed masses.

## Amendment 1 (after `gate.replay`; before any smoke run)

**Failure.** `gate.replay` exited 1: the replay harness threw `map::at` before writing any row.

**Cause.** The harness's `split` (in `tests/compound_annotation_test.cpp`) dropped a trailing empty field. Dump rows of
**empty alleles** (zero-length sequence) therefore lost their `sequence` column. This is a test-harness defect. The
library's declaration parser is unaffected: its lines never end in an empty field.

**Fix.** The harness `split` keeps trailing empty fields. Nothing else changes.

**Rerun:**
- `build.a1` (test binary only);
- `gate.compound_unit.a1`;
- `gate.replay.a1`, which replaces `gate.replay` in the smoke precondition.

The failed unit stays recorded.

## Amendment 2 (after `gate.replay.a1`; before any smoke run)

**Failure.** `gate.replay.a1` exited 1: `std::stod` threw `out_of_range` on **subnormal** printed masses (for example about
1e-310). It reports underflow as an error, whereas Python's `float()` parses them.

**Scope.** A test-harness defect only. The caller never parses masses: it uses in-memory doubles.

**Fix.** The harness parses masses with `std::strtod`, which returns the subnormal value. Nothing else changes.

**Rerun:** `build.a2`, `gate.compound_unit.a2` and `gate.replay.a2`, which replace the A1 units in the smoke precondition.

## Amendment 4 (after `smoke_check.a3`; no caller run follows)

**What `smoke_check.a3` found.** Every scientific output is identical: 73 of 76 identity checks pass, and 29 of 31 thread
checks pass, including both annotation files.

**Why it failed.** Some differing `mosaic_status` keys fell outside the declared patterns. Their values were inspected:
- **`emission_cache_dp_hits` / `emission_cache_dp_misses`:** cache-work split counters. Hits + misses = 2,054,744 in
  both arms; only the split varies. This is the known run-to-run cache-work variation at 4 threads.
- **`profile`, `profile_name`, `profile_sha256`:** the provenance of the added compound profile file. The design allowed
  `profile` only in `settings.tsv`.
- **The 1- against 4-thread comparison:** thread-count and work-partition keys (`threads_*`, `adaptive_fine_units_*`,
  `adaptive_fine_worker_*`, `settings_overridden_after_profile`) and the settings `threads` value. These differ by
  construction when the thread count differs.

**Fix.** These keys are declared explicitly (`AMENDMENT4_KEYS`, and `THREAD_KEYS` for the thread run only). No scientific
file, column or other key is excluded.

**Rerun:** `smoke_check.a4`. `smoke_check.a3` stays recorded.
